# Release Blockers

Do not publish a paid beta until every row has concrete evidence in the named
location. Keep secrets, license keys, certificates, and private store IDs out of
this file.
For the shortest cross-track status and blocker-type summary, also see
[docs/objective-audit.md](/Users/masakitakemura/_workspace/drop-squash/docs/objective-audit.md).
Use `Blocked` until the evidence exists. Change a row to `Verified` only after
the evidence is recorded in the named location.
Do not leave a row `Blocked` after adding an `Evidence reference`; update the
status and keep the reference traceable.
For `Verified` rows, `Evidence reference` must point to `docs/...`, an
`https://...` URL, `Release notes`, `GitHub Release`, or `Homebrew tap PR`.
Public website, pricing, and refund references must use the production
`dropsquash.app` host.
Owner-only or access-controlled Sites URLs do not count as public website,
pricing, or refund blocker evidence.
Checkout references must use the live `store.lemonsqueezy.com/checkout/buy/<id>` URL.
Public website, pricing, refund, and checkout references must not include query or fragment parts.
`GitHub Release` and `Homebrew tap PR` references must include the public URL.
Use the exact forms `GitHub Release https://...` and
`Homebrew tap PR https://...` without extra words in the Evidence reference.
When re-running packaged-app or license manual QA before those rows are updated,
prefer a fresh isolated build such as
`CARGO_TARGET_DIR=/tmp/dsq-build-target pnpm --dir apps/desktop tauri build`
and use `/tmp/dsq-build-target/release/bundle/macos/DropSquash.app` if the
default `target/` tree is stale or no longer matches the current sources.
